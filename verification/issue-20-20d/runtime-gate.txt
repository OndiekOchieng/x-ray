=== the reviewer chain, as it now runs ===
composeLiveRuntime            -> constructs the ReviewerModel
registerLiveProviders         -> installs it via setReviewerModelProvider
                                 (its own seam: StageAdapters has no reviewer member,
                                  because a research stage must not be handed one)
assessCandidate               -> getReviewerModel()          <- THE CONSUMING HOP
  (application orchestration)    explicit options.model wins; otherwise the seam
ATIResearchBridge.processIntake-> assessCandidate(this.graduation, ...)
GraduationService.assess      -> collectModelJudgments(candidate, model)
                              -> assessGraduation(candidate, { model, judgments })
                              -> reviewXRayGraph(graph, { validation, model, judgments })
                                 ... which is pure, and no network call happens inside it

Two defects, fixed in two rounds, both leaving the same symptom:
  first submission  - nothing installed the reviewer, and assess() passed `model`
                      into the SYNCHRONOUS reviewXRayGraph, which does not collect
  second submission - installed into the seam, and no application path read it
Either way a fully configured deployment reported the capability and left every
model-assisted check NOT_EVALUATED.

GraduationService never reads the seam. It receives a ReviewerModel, so its
dependencies stay visible and a harness can drive it without arranging a global.
Exactly one application file reads the seam, and the gate asserts that.

reviewer absent   -> model-assisted checks NOT_EVALUATED with a reason;
                     graduation BLOCKED; fullCapability false. No PASS exists to
                     collapse into: ReviewOutcome is EVALUATED | NOT_EVALUATED.
reviewer refuses  -> the asked checks stay NOT_EVALUATED with a reason; no review
                     finding and no graduation reason about the graph
reviewer throws   -> an outage, not a capability gap; propagates, no assessment is
                     appended, so commit() has nothing to stand on

Requirements <-> CONSUMED capabilities:
  REQUIRED_SLOTS = RESEARCH_MODEL, REVIEWER_MODEL, RETRIEVAL
  research model + retrieval reach the pipeline through the runtime's StageAdapters
  reviewer reaches the REVIEW gate and graduation through assessCandidate, which
    resolves the seam
  -> every required slot has a CONSUMER, not merely a registration. A reviewer
     installed into a slot nobody reads fails check 3b and check 20b.

=== retrievedAt ===
observedAt(provided, now):
  a provider value that is a real ISO instant  -> used
  anything else, or absent                     -> the injected clock, now()
Before: `document.retrievedAt ?? ctx.correlation.investigationId` — an investigation
id where a timestamp belongs. It typechecked because both are strings, and every
fixture supplied a retrievedAt so the fallback never ran.
Verified backstop: with the bad fallback restored, INGEST fails
STRUCTURAL/NON_ISO_TIMESTAMP and no source is minted. The bug was latent, not
silent-corrupting — but it would have failed any live run where a provider omitted
the timestamp.
