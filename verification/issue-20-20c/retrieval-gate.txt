=== API contract implemented ===
Verified against official documentation on 2026-09-21:
  https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool
  https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool
  https://platform.claude.com/docs/en/api/messages          <- the reference

The guide and the reference DO NOT AGREE on the web-fetch error vocabulary.
The tool guide lists nine codes; the API reference lists ten, adding
content_too_large. The vocabulary follows the reference, which is the wider and
therefore safer source. The first 20c submission was built from the guide alone
and was missing a documented code.

Implemented:  web_search_20250305   with allowed_callers: ["direct"]
              web_fetch_20250910    with allowed_callers: ["direct"],
                                    citations disabled, max_content_tokens

Available but deliberately NOT used:
  web_search_20260209 / web_search_20260318
  web_fetch_20260209  / web_fetch_20260309 / web_fetch_20260318
Their headline feature is dynamic filtering: the model writes and runs code
that filters results before they reach the context window. On those versions
allowed_callers defaults to ["code_execution_20260120"], so filtering is the
default rather than an opt-in. That is a provider pruning a result set by
relevance before anything crosses the retrieval boundary — an evidentiary
judgement made where no invariant can see it. XR-INV-006 turns on the extent of
the search and 6c's stop assessment on "we stopped" vs "nothing left"; neither
question can be answered about an already-pruned set.

Documented facts that shaped the code:
  - a search/fetch error returns HTTP 200 with a *_tool_result_error block
  - a search matching nothing returns an EMPTY content list, not an error
  - page_age is "when the site was last updated", example "April 30, 2025"
    — not a publication date, and not ISO 8601
  - web fetch can only reach a URL already in the conversation
  - web fetch does not render JavaScript
  - stop_reason "pause_turn" is continued by resending the assistant message

=== outcome mapping ===
SEARCH
  a web_search_result                      NOT_RETRIEVED   (url + title + opaque
                                                            encrypted_content: a record
                                                            identified, not obtained)
  empty content list                       no document at all + no moreAvailable
  max_uses_exceeded                        0 documents + moreAvailable: true
  too_many_requests / unavailable          AdapterFailure TRANSIENT
  query_too_long / invalid_tool_input
    / request_too_large                    Capability REFUSED_FOR_INPUT
  an unrecognised error code               AdapterFailure PERMANENT
  no search run at all                     AdapterFailure PERMANENT
  stop_reason pause_turn                   AdapterFailure TRANSIENT

FETCH
  text document, untruncated               RETRIEVED  + extract + our digest
  text document, truncated by bound()      PARTIAL    + extract + our digest
  base64 / non-text (e.g. PDF)             NOT_RETRIEVED, no extract, reason disclosed
  url_not_accessible                       DEAD_LINK
  url_not_allowed                          NOT_RETRIEVED
  unsupported_content_type                 NOT_RETRIEVED
  content_too_large                        NOT_RETRIEVED  (reached; no content returned.
                                                           NOT PARTIAL: partial means a
                                                           stage may read incomplete
                                                           content, and none arrived)
  too_many_requests / max_uses_exceeded
    / unavailable                          AdapterFailure TRANSIENT
  invalid_tool_input / url_too_long        Capability REFUSED_FOR_INPUT
  url_not_in_prior_context                 AdapterFailure PERMANENT (our defect)
  no fetch attempted                       AdapterFailure PERMANENT
  stop_reason pause_turn                   AdapterFailure TRANSIENT

NOT_LOCATED is reachable through the vocabulary but is never asserted by this
adapter: a search that matched nothing yields no document rather than one
claiming absence, and a 404 is DEAD_LINK. DOES_NOT_EXIST is unreachable — the
type has no such member and no mapping produces one.

DEDUPLICATION
  Exact equality of normalised locators. normalizeLocator has already removed
  everything safely removable (scheme/host case, default port, fragment), so
  anything still different is a difference in the resource.

  distinct:   /Records/Award.PDF   vs  /records/award.pdf
              /record              vs  /record/
              ?id=ABC              vs  ?id=abc
              ?DocumentId=42       vs  ?documentId=42
  collapses:  HTTPS://EXAMPLE.invalid/a, https://example.invalid:443/a,
              http://example.invalid:80/a, https://example.invalid/a#part-2,
              "  https://example.invalid/a  "

PAUSE_TURN — decision recorded in retrieval-contract.ts, asserted by check 26
  It is continuation, not a pipeline retry.
  The final implementation resends the paused assistant message unchanged,
  including every encrypted_content, to resume the same turn.
  It belongs at the Anthropic server-tool transport/session boundary, NOT in
  generic pipeline retry logic, which knows nothing about provider turns.
  20c reports TRANSIENT as a disclosed placeholder; the thrown message says
  "not implemented in 20c" so a re-driven stage is not read as a completed
  search.
